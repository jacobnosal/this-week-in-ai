## Policy & Regulation

- **EU AI Act — enforcement powers went live August 2, 2026.**
  From Aug 2, the Commission/AI Office can request documentation, run technical model evaluations, demand
  risk-mitigation, restrict/withdraw a model from the EU market, and **issue fines**. GPAI obligations have
  applied since Aug 2025 but the one-year adjustment period ended Aug 2, 2026 — so **fines can now bite**.
  Also live: Annex III high-risk obligations (Arts. 8–15) and Art. 50 transparency for AI-generated/manipulated
  output. GPAI Code of Practice signing remains voluntary but confers a "presumption of conformity" safe harbor.
  - Sources: EU AI Act (artificialintelligenceact.eu) enforcement of Chapter V https://artificialintelligenceact.eu/enforcement-of-chapter-v-under-the-eu-ai-act/ ; beam.ai https://beam.ai/agentic-insights/eu-ai-act-enforcement-august-2-2026-gpai-fines
  - RESOLVES prior "What to Watch" (2026-24): the Aug 2, 2026 high-risk/GPAI-enforcement default arrived on schedule.

## Enterprise & Security Implications

- **OpenAI Daybreak partner program — Accenture is a named vetted partner.**
  Two tiers: **Daybreak Blue** (Sol + general models with defensive guardrails) and **Daybreak Red**
  (specialized cyber models incl. GPT-5.6-Cyber). Red requires identity verification, legal attestations,
  approved use cases. Named partners reportedly include **Accenture, Capgemini, EY, IBM, KPMG, PwC, Palo Alto
  Networks, CrowdStrike, Sophos, Fortinet, Akamai, Cloudflare.**
  - Source: SecurityWeek https://www.securityweek.com/openai-unveils-new-cybersecurity-model-gpt-5-6-cyber/
  - SDC angle: vetted access to a frontier offensive-cyber model is now a gated commercial capability SDC
    partners can hold; raises authorization, attestation, and dual-use-governance questions for client work.

- **CVE-2026-22708 — Cursor agent allowlist bypass (fixed in 2.3).**
  In Auto-Run + Allowlist mode, shell **built-ins** (export, unset, set, typeset, etc.) execute without
  appearing in the allowlist or prompting for approval. Via direct/indirect prompt injection an attacker
  poisons env vars so allowlisted commands (git branch, python3 script.py) become arbitrary code execution —
  zero-click RCE even with an empty allowlist. Related: **CVE-2026-26268** (git-hook arbitrary code execution
  in Cursor).
  - Sources: SentinelOne https://www.sentinelone.com/vulnerability-database/cve-2026-22708/ ; Pillar Security https://www.pillar.security/blog/the-agent-security-paradox-when-trusted-commands-in-cursor-become-attack-vectors ; Novee (CVE-2026-26268) https://novee.security/blog/cursor-ide-cve-2026-26268-git-hook-arbitrary-code-execution/
  - SDC generalization: command allowlists on agentic dev tools are **not** a security boundary if shell
    built-ins / env expansion are in scope. Continues the "when prompts become shells" pattern from the
    Semantic Kernel CVEs (2026-24). OWASP 2026 reportedly logs a 340% YoY surge in prompt-injection attacks;
    "prompt injection remains unsolved" per OWASP researchers.
  - Sources: Help Net Security https://www.helpnetsecurity.com/2026/06/11/owasp-prompt-injection-ai-security-failures/
