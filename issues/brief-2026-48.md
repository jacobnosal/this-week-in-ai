## Enterprise & Security Implications

### AWS Bedrock AgentCore — "AgentCorruption" credential-boundary chain (Zenity Labs; AWS disputes)
- Zenity Labs disclosed a prompt-injection → cloud-credential-theft chain against Amazon
  Bedrock AgentCore. A public-facing agent with web-request tooling could be prompted to
  hit the instance metadata endpoint (169.254.169.254) and retrieve credentials tied to
  its execution role.
- Root causes: use of IMDSv1 + an overly broad default execution role. Stolen permissions
  reached other agents in the same account/region — reported access to private chats,
  source code, long-term memories, and secrets (incl. AWS Secrets Manager).
- Timeline: metadata exposure reported Dec 2025; AWS moved AgentCore to IMDSv2 by Feb 2026;
  broader over-permissioned-role issue resolved ~end of Sept 2026.
- AWS disputes the "vulnerability" framing — says it describes expected/documented behavior,
  no cross-account boundary crossed, fully mitigated.
- Unit 42 (Sep 18, 2026) separately showed indirect prompt injection driving an AgentCore
  Harness to run as root and read runtime-memory credentials.
- Ongoing operational theme rather than brand-new this week; strongest concrete SDC talking point.
- Sources: [SC World](https://www.scworld.com/brief/amazon-bedrock-agent-vulnerability-allowed-credential-theft-and-code-access) ·
  [The Decoder / Zenity](https://the-decoder.com/a-single-prompt-was-enough-to-hijack-every-ai-agent-in-an-aws-account-zenity-researchers-found/) ·
  [Cybersecurity News](https://cybersecuritynews.com/agentcorruption-attack/)
