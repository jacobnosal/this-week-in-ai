At a Glance

The week’s clearest signal was a security one. A single industry roundup catalogued a wave of agentic-AI exploits disclosed by multiple research teams — led by Check Point’s bypass of OpenAI’s ChatGPT Lockdown Mode (the anti-prompt-injection control introduced in June, patched Sept 18), alongside credential-theft and zero-click data-exfiltration attacks against AWS Bedrock AgentCore, Salesforce Agentforce, and the built-in browsers and plugin supply chains of popular coding agents (Claude Code, Codex, GitHub Copilot, Gemini CLI). The through-line: once an agent holds real tool authority and sees untrusted content, prompt injection stops being a bad output and becomes active compromise. Model-release and funding activity this week (early-November OpenAI image models; reported OpenAI and Meta acquisitions; Anthropic IPO chatter) traces mostly to third-party trackers and aggregator blogs and is flagged below for human verification before client use.

Safety & Research

The Hacker News — Agentic-AI exploit roundup (Nov 5) Multiple research teams disclosed a cluster of attacks against agentic AI systems. Headline finding: Check Point (research head Eli Smadja) bypassed OpenAI’s ChatGPT Lockdown Mode — the optional anti-exfiltration setting launched June 2026 — by nesting sandboxed iframes inside ChatGPT’s HTML code-block previews to reach an unmodified popup function and escape the mode’s outbound restrictions, enabling silent/zero-click chat-data theft in the desktop app. OpenAI reportedly patched it on Sept 18, 2026 following responsible disclosure. The same report names, among others: AgentCorruption (Zenity Labs — prompt injection on an exposed AWS Bedrock AgentCore agent to steal IMDS credentials and pivot), SalesBleed (Zenity Labs — zero-click account-data extraction from Salesforce Agentforce via a Web-to-Lead form), and Plugin4Shell (Air Security — a supply-chain swap that bypasses SHA pinning for RCE in Claude Code, Codex, GitHub Copilot, and Gemini CLI).

💡 Why it matters — This is the first week where agentic-AI exploits read like a conventional vuln-disclosure cycle: named bugs, named vendors, responsible disclosure, patch dates. The common factor across every item is an agent that holds tool authority and ingests untrusted content — the pattern enterprises now have to threat-model directly.

REVIEW: Individual exploit names (AgentCorruption, SalesBleed, Plugin4Shell, Embrace, BragJack, PleaseFix, SkillJacking) and most vendor patch statuses come from a single roundup and could not be independently confirmed against each vendor’s own advisory. Confirm per-item patch status before citing specifics to a client.

Enterprise & Security Implications

Agentic exploits are now a disclosure category — threat-model the tool authority, not the model. The Nov 5 roundup clusters into three practical client talking points: - Tool-authority least-privilege. AgentCorruption-style attacks turn an injected prompt into credential theft (IMDS) and lateral movement. Confirm agent service accounts and tool scopes follow least-privilege and that agentic workflows can’t silently invoke high-privilege identities. - Supply chain for agent extensions. Plugin4Shell reportedly bypassed SHA pinning to achieve RCE in mainstream coding agents. Pinning alone is not integrity — validate plugin/skill provenance and update channels. - Untrusted content into agent context. SalesBleed (Web-to-Lead form) and PleaseFix (emails/calendar invites) show attacker-controlled content reaching agents through ordinary business intake. Treat any untrusted-content path into an agent as an injection surface.

🛡️ Why it matters for SDC — This maps cleanly onto an assume-breach agent architecture: least-privilege tool scopes, provenance-checked extensions, and sanitization at every untrusted-content ingestion point. It is a ready-made structure for a client agentic-AI risk conversation this quarter.
